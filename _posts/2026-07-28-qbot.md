## Scenario
A company's security team detected unusual network activity linked to a potential malware infection. As a forensic analyst, your mission is to investigate a memory dump, identify the malicious process, extract artifacts, and uncover Command and Control (C2) communications. Using Volatility3, analyze the attack, trace its origin, and provide actionable intelligence.

Hoạt động mờ ám thông qua network thì đó là điều đáng chú ý, nhưng malware hoạt động thì chưa bao giờ hoạt động một mình, hôm nay mình sẽ thực hiện detected về những hành động này bên cạnh đó sẽ thực hiện investigation về **ENDPOINT** bị malware injection, ngoài việc điều tra nguồn gốc thì kèm theo đó còn phần tích malware static và có khả năng nếu khó hiểu thì sẽ thực hiện dynamic malware trong **SandBox** để detect và xem behavior của malware này không chỉ scope nằm trong Endpoint này mà còn sau này nữa.

Đây không phải là một file memory mà đây là một file ram đã được *dump* ra để mình thực hiện phân tích và điều tra vụ này, trước hết phải kiểm tra những gì đang và run ở trong ram trước khi nó bị dump ra.

### Tổng hợp IOCs
Dựa trên các artifact thu được từ memory dump và file Excel dump, có thể tổng hợp các IOCs chính như sau:

| Loại IOC | Giá trị | Ý nghĩa |
| --- | --- | --- |
| File lure | `Payment.xls` | Tệp Excel lừa đảo dùng làm vector thực thi macro. |
| Hash malware | `91610c69484cace41e411396aa48846879b140b1678c9dbe1d86fff4ae0bd65d` | Hash SHA-256 của mẫu Excel chứa mã độc, dùng để tra cứu trên VirusTotal hoặc hệ thống threat intel. |
| Hash dump | `3cef2e4a0138eeebb94be0bffefcb55074157e6f7d774c1bbf8ab9d43fdbf6a4` | Hash của file dump từ memory, có thể dùng để đối chiếu với mẫu thu được từ endpoint. |
| Process | `EXCEL.EXE` (spawn từ `explorer.exe`) | Chứng minh người dùng đã mở file Excel bằng tay, không phải hệ thống tự chạy. |
| C2 / IP | `94.140.112.73`, `45.147.230.104`, `185.244.150.147` | Các endpoint có khả năng liên quan đến kết nối C2 hoặc tải payload. |
| URL | `http://185.244.150.147/`, `http://94.140.112.73/`, `http://45.147.230.104/` | URL xuất hiện trong macro hoặc quá trình tải xuống, có thể là điểm tải payload hoặc C2. |
| Dropped artifacts | `Lifas.ver`, `Lifas.ver1`, `Lifas.ver2` | Các file được macro tạo hoặc tải về, có thể là module phụ hoặc payload. |
| Macro indicators | `Auto_Open`, `URLDownloadToFileA`, `Workbook_BeforeClose`, `regsvr32 -silent` | Chỉ dấu cho macro VBA thực hiện tải xuống và thực thi mã độc. |
| Macro technique | `Excel 4.0 Macro (XLM)`, `Excel4IntlMacroSheets.Add` | Tài liệu sử dụng kỹ thuật Excel 4.0 Macro Sheet để né phát hiện macro VBA truyền thống. |
| XLM function | `REGISTER`, `EXEC` | Có khả năng đăng ký hoặc gọi hàm DLL/API, đồng thời thực thi lệnh hệ thống từ macro. |
| LOLBin / Process | `regsvr32.exe` | Windows Living-off-the-Land Binary được dùng để nạp hoặc thực thi payload. |
| Command line | `regsvr32 -silent ..\Lifas.ver` | Lệnh thực thi payload ở chế độ im lặng. |
| Hunting artifact | `Nneeri`, `Kopast`, `Hrosters`, `Diopaster`, `Biolaster`, `dfgdf` | Tên hàm/module bất thường có thể dùng làm dấu hiệu hunting cho các mẫu tài liệu cùng chiến dịch. |

#### Chuỗi tấn công có khả năng xảy ra

```text
Người dùng mở tài liệu Excel
        ↓
Macro auto_open được kích hoạt
        ↓
Tạo/chạy Excel 4.0 Macro Sheet
        ↓
Ghép URL chứa 185.244.150.147
        ↓
URLDownloadToFileA tải payload
        ↓
Lưu dưới tên ..\Lifas.ver
        ↓
regsvr32 -silent ..\Lifas.ver
        ↓
Payload được nạp/thực thi
```

#### Các dấu hiệu hành vi quan trọng

- Tự động thực thi khi mở file: `Sub auto_open()`.
- Tải mã từ Internet: `URLDownloadToFileA` và `http://185.244.150.147/`.
- Che giấu payload bằng phần mở rộng không thông thường: `Lifas.ver`, `Lifas.ver1`, `Lifas.ver2`.
- Sử dụng công cụ hệ thống để thực thi: `regsvr32`.
- Thực thi không hiển thị giao diện: tham số `-silent` hoặc `-s ilent` trong strings bị chia nhỏ.
- Né phân tích macro truyền thống: `Excel4IntlMacroSheets.Add`, `REGISTER`, `EXEC`.

#### Giải thích về IOCs
IOC (Indicators of Compromise) là những dấu hiệu cho thấy một hệ thống đã bị compromise. Trong trường hợp này, các IOC giúp SOC và analyst xác định nhanh các yếu tố sau:

- Hash giúp tra cứu và chặn mẫu malware trên các công cụ EDR, SIEM hoặc Threat Intelligence.
- IP và URL giúp phát hiện các kết nối bất thường ở tầng mạng, proxy, firewall hoặc DNS.
- Tên file và artifact bị drop giúp tìm kiếm trên endpoint để kiểm tra xem có file nào tương tự còn tồn tại hay không.
- Các dấu hiệu macro như `Auto_Open` và `URLDownloadToFileA` cho thấy vectơ lây nhiễm là Excel macro-based malware, không phải một file độc thông thường.
- Các dấu hiệu XLM macro như `Excel4IntlMacroSheets.Add`, `REGISTER` và `EXEC` cho thấy tệp có thể đang sử dụng kỹ thuật thực thi ẩn và né phát hiện.

#### Ứng dụng trong phản ứng sự cố
1. Chặn hash, IP và URL này trên EDR, firewall, proxy hoặc DNS filtering.
2. Quét endpoint để tìm `Payment.xls`, `Lifas.ver*` và các macro liên quan.
3. Kiểm tra log network, proxy và DNS xem có bất kỳ kết nối nào tới các IP/URL trên hay không.
4. Đưa các IOCs này vào Threat Intelligence để tăng khả năng phát hiện cho cárênc sự cố tiếp theo.
