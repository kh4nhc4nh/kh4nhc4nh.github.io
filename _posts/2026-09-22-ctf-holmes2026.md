### Question 1

**Question: “To which directory does the application copy the files bundled within the extraResources folder? (*:\path\to\dir)”**

What is the question actually asking?

It asks for the destination directory of the files that the Electron application copies from its extraResources directory. It is not asking where extraResources itself lives and it is not asking where settlement.html is later written.

Where to look

Look in the Electron main-process code for fs.readdirSync, fs.copyFileSync, extraResources, or C:\Users\Public. The supplied source contains the relevant code:

fs.readdirSync(path.resolve(`${process.resourcesPath}/../extraResources`))
  .forEach(f => fs.copyFileSync(
      path.resolve(`${process.resourcesPath}/../extraResources`, f),
      path.join('C:\Users\Public', f)
  ));

Why this answers the question

The source explicitly constructs the destination with path.join('C:\Users\Public', f). Because f is the filename being copied, the directory is C:\Users\Public. There is no need to infer it from Electron installation conventions or from an environment variable.

How to reproduce

Open main.js (or the extracted JavaScript responsible for application initialization).

Search for extraResources or copyFileSync.

Read the second argument of the copy operation together with its base path.

Return only the directory requested by the question, matching its *:\path\to\dir format.

*ANSWER: C:\Users\Public*

### Question 2

**Question: “Which Win32 structure defines the format of the buffer returned by the Lua script when monitoring directory changes? (string)”**

What is the question actually asking?

The question is not asking for the API that performs monitoring. It asks for the Win32 structure that describes the layout of the change-notification buffer returned by ReadDirectoryChangesW.

Where to look

This belongs to api.txt. The LuaJIT script is obfuscated, so first recover the Win32 API names/FFI declarations. The relevant behavioral chain is:
```java
CreateFileW(...)
        ↓
ReadDirectoryChangesW(...)
        ↓
lpBuffer contains directory-change records
        ↓
FILE_NOTIFY_INFORMATION
```

Why the structure is FILE_NOTIFY_INFORMATION

ReadDirectoryChangesW documents that the lpBuffer results are returned in a format defined by FILE_NOTIFY_INFORMATION. The structure contains fields such as NextEntryOffset, Action, FileNameLength, and FileName. This is the exact distinction the question is testing: API vs. buffer structure.

Reference: Microsoft Learn, ReadDirectoryChangesW; Microsoft Learn, FILE_NOTIFY_INFORMATION. The documentation states that lpBuffer is a formatted buffer whose structure is defined by FILE_NOTIFY_INFORMATION. [Web verification: Microsoft Learn, searched 2026-09-22.]
```java
typedef struct _FILE_NOTIFY_INFORMATION {
    ULONG NextEntryOffset;
    ULONG Action;
    ULONG FileNameLength;
    WCHAR FileName[1];
} FILE_NOTIFY_INFORMATION, *PFILE_NOTIFY_INFORMATION;
```

How to solve from the sample

Deobfuscate or string-decode api.txt until ReadDirectoryChangesW and the relevant FFI declarations are visible.

Recognize that the question asks what format the returned buffer uses.

Map ReadDirectoryChangesW → lpBuffer → FILE_NOTIFY_INFORMATION.

*ANSWER: FILE_NOTIFY_INFORMATION*

### Question 3

**Question: “Which Win32 API is used by the Lua script to send an HTTP request to the remote server? (string)”**

What is the question actually asking?

The key distinction is between APIs that prepare a request and the API that actually sends it. api.txt uses the WinHTTP family of functions. WinHttpOpenRequest prepares/creates a request handle; WinHttpSendRequest sends the request.

Where to look

After deobfuscating api.txt, identify the WinHTTP FFI imports/calls. The relevant family is WinHttpOpen, WinHttpConnect, WinHttpOpenRequest, WinHttpSendRequest, and WinHttpReceiveResponse.
```java
WinHttpOpen(...)
    ↓
WinHttpConnect(...)
    ↓
WinHttpOpenRequest(...)
    ↓
WinHttpSendRequest(...)
    ↓
WinHttpReceiveResponse(...)
```

Why WinHttpSendRequest

The question says “used ... to send an HTTP request”. Microsoft Learn defines WinHttpSendRequest as the function that sends the specified request to the HTTP server. Therefore the answer is the send function, not WinHttpOpenRequest.

Reference: Microsoft Learn, WinHttpSendRequest. [Web verification: Microsoft Learn, searched 2026-09-22.]

*ANSWER: WinHttpSendRequest*

Step 4 – read the decrypt algorithm

keyByte = key[i % key.length]
step1 = data[i] ^ keyByte
step2 = ((step1 << 7) | (step1 >>> 1)) & 0xff
plaintextByte = step2 ^ 0x42

The 7-bit rotation is a byte rotation. Because the value is constrained to 8 bits with & 0xff, the operation is effectively an 8-bit rotate-left by 7 bits (equivalently rotate-right by 1 bit).

result = bytearray()

The plaintext itself is a command. The second half contains the string that matches the exact challenge format supplied in the question. Do not confuse the command path (%TEMP%\settlement.html) with the flag value.
